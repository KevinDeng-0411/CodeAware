## 1. 阶段目标与用户可见结果

完成后：

1. 应用存在可持久化的 Project，前端全局项目选择器显示当前项目。
2. 用户切换项目后，Chat 会话、Knowledge、Long-term Memory、Code Review/Unit Test 记录和 AI ReadMe 只显示当前项目的数据。
3. 所有项目级 API 以 `X-Project-ID` 为唯一作用域来源；自由文本 `project_name` 不再承担隔离职责。
4. 同一个搜索词在两个项目分别写入不同资料时，检索结果互不泄漏。
5. 拿项目 B 的 header 读取或删除项目 A 的整数 ID/cid，只得到统一“未找到”，项目 A 数据保持不变；这证明隔离谓词正确，不代表调用者已经通过身份授权。
6. 从 C3 冻结的当前版本升级时，历史数据全部归入确定性的默认 `Local` 项目，不产生空 `project_id`。
7. 全新数据库和已有数据数据库均可升级；迁移 downgrade 的数据风险被明确验证。

本阶段结束后，默认 S2/S4/S5 与可选 S3 都可以依赖一个强约束：任何 Chat context、
repository、Tool 或未来 Graph node 都必须显式携带服务端从 `X-Project-ID` 解析出的
`project_id`，不能执行无作用域读取。

## 5. 稳定数据模型

### 5.1 Project

新增 `codeaware-py/app/models/project.py`：

```python
class Project(Base):
    __tablename__ = "projects"

    id: Mapped[UUID]              # UUID PK，应用创建时 uuid4()
    slug: Mapped[str]             # 唯一、不可空，供人识别，不参与数据 join
    name: Mapped[str]             # 显示名
    is_default: Mapped[bool]      # 默认项目标记
    created_at: Mapped[datetime]  # server_default=func.now()
```

固定默认项目：

```text
id         = 00000000-0000-0000-0000-000000000001
slug       = local
name       = Local
is_default = true
```

在一个共享 Python 常量中定义该 UUID，migration 中写字面值；不要在 migration 导入应用代码。`is_default=true` 建部分唯一索引，确保至多一个默认项目；seed 确保至少一个。

Project 创建 API 只接受：

```python
class ProjectCreate(BaseModel):
    slug: Annotated[str, Field(pattern=r"^[a-z0-9][a-z0-9-]{0,62}$")]
    name: Annotated[str, Field(min_length=1, max_length=120)]
```

S1 不允许 API 创建第二个 default，不提供 update/delete。

### 5.2 五张项目级表

以下 ORM 增加 `project_id: UUID`，全部 `nullable=False`、FK `projects.id`、`ondelete=RESTRICT`、普通 B-tree index：

- `Conversation`
- `Document`
- `LongTermMemory`
- `AiOperationRecord`
- `AiReadmeDocument`

保留：

- `Conversation.conversation_id` 的全局唯一约束。这样现有 `Message.conversation_id` FK 和 Redis key 无需在 S1 破坏性重建。
- `Document.project_name`、`AiOperationRecord.project_name`、`AiReadmeDocument.project_name` 作为兼容/显示元数据，但任何隔离判断不得使用它们。
- Message/Chunk 到父表的现有级联关系。

所有新写入必须由服务显式赋值 `project_id`。数据库 migration 用临时 server default 或显式 UPDATE 完成历史回填后，应移除 server default，让遗漏作用域的代码在测试/运行时尽早失败，不能静默落入 Local。

## 7. `X-Project-ID` 契约

### 7.1 哪些端点需要

必须携带合法 `X-Project-ID`：

- `/api/chat/**`
- `/api/knowledge/**`
- `/api/memory/**`
- `/api/code-review/**`
- `/api/unit-test/**`
- `/api/ai-readme/**`

不需要：

- `/health`
- `/api/ai/health`（按实际现有路径）
- `/api/projects` 的 list/create
- `/api/prompts/**`（S1 Prompt 仍全局）
- `/docs`、`/openapi.json`、静态前端

### 7.2 解析与错误

在 `app/api/v1/deps.py` 定义一个项目 dependency，返回不可变 `ProjectScope`：

```python
@dataclass(frozen=True)
class ProjectScope:
    actor_id: Literal["local-single-user"]
    project_id: UUID
    project_slug: str
    project_name: str
```

规则：

1. 对项目级 `/api/**`，`X-Project-ID` header 必填；不从 query、cookie、body `project_id`、`project_name` 或 Local default 隐式推断。
2. 只接受标准 UUID；前后空白可由 Header parser 正常处理，值内部不可修复。
3. UUID 必须存在于 `projects`。
4. 缺失/格式错误：HTTP 400，错误码 `INVALID_REQUEST`。
5. 未知 Project：HTTP 404，错误码 `PROJECT_NOT_FOUND`；这不是 401/403，也不宣称做过用户授权。
6. 某对象不存在或属于别的项目：统一 HTTP 404 和相同“资源不存在”消息，不能暴露对象实际存在于其他项目。
7. 公共请求体、query 和 Tool 参数不得新增 `project_id`。若 C3 兼容 body 暂时已有该字段，只能在明确删除期内与 header 做相等校验，不得独立生效；不一致返回 `PROJECT_SCOPE_MISMATCH`。
8. `actor_id` 始终由服务端写成 `local-single-user`，客户端不能通过任意传输字段覆盖。

所有 JSON endpoint 继续使用 C3 OpenAPI 冻结的 `Result[T]`：`{"code":1,"msg":"success","data":...}`。失败保留同一 envelope 并增加稳定 `error_code`；HTTP status 仍表达传输结果。不得为 Project API 创建裸数组或第二套错误 body。测试必须断言 HTTP status、业务 code 和 `error_code`，不能只看 message 文本。

重要安全说明：当前没有真实 actor/membership；sentinel 只用于本地审计和幂等。持有某 Project UUID 的本地客户端即可选择它。S1 只防止应用内部无意串数据和跨 header 访问，不宣称已经完成用户授权；应用必须保持 loopback-only。

## 8. 全链路过滤矩阵

任何项目级方法的签名都必须显式接收 `project_id: UUID` 或 `ProjectScope`，不能用可选参数默认全库。

| 域 | 写入 | list/search | get/delete/关联校验 |
|---|---|---|---|
| Chat | 新 Conversation 写 header project_id | Conversation list 加 `Conversation.project_id == scope.id` | 读消息、续聊、删会话前先以 `project_id + conversation_id` 找父会话 |
| Knowledge | Document 写 project_id | vector 腿、keyword 腿和多 query 去重前都限定父 Document project | delete 用 `id + project_id`，不能 `session.get(Document,id)` |
| Memory | 手工/抽取 Memory 写 project_id | 每次 vector recall 加 `LongTermMemory.project_id` | delete 用 `id + project_id`；传 conversation_id 时验证 Conversation 同项目 |
| Chat context | LTM recall 与 RAG search 都传相同 scope | 不允许降级为无 scope 查询 | scope 查询失败可按现有非致命策略降级，但不能尝试全库 fallback |
| Code Review | record 写 header project_id | list 和 total 同时按 project_id + type + 可选 project_name | detail 按 project_id + id + `type=CODE_REVIEW` |
| Unit Test | record 写 header project_id | list 和 total 同时按 project_id + type + 可选 project_name | detail 按 project_id + id + `type=UNIT_TEST` |
| AI ReadMe | document 写 header project_id | 当前无 list；未来 list 必须作用域化 | get 按 project_id + path project_name |

### 8.1 向量/混合检索

不要给通用 `VectorRecallService.recall()` 暴露一个默认空 tuple 的任意 SQL filter；那会让调用方轻易漏传 scope，也把 SQLAlchemy 表达式泄漏到 application 层。对项目实体定义两个无缺省 scope 的领域入口，例如：

```python
async def recall_memories(
    scope: ProjectScope,
    query: str,
    *,
    threshold: float,
    top_k: int,
) -> list[RecalledMemory]: ...

async def search_knowledge(
    scope: ProjectScope,
    query: str,
    *,
    top_k: int,
) -> list[KnowledgeResult]: ...
```

实现要求：

- adapter 内部从 `scope.project_id` 构造固定谓词，并同时应用到 vector statement 和 keyword statement；
- public project-scoped 方法没有 `scope=None`、空 tuple 或默认全库重载；
- LongTermMemory 用 `LongTermMemory.project_id == project_id`；
- KnowledgeChunk 本身不复制 project_id，使用
  `KnowledgeChunk.document.has(Document.project_id == project_id)`，或等价的显式 JOIN；
- 两条检索腿必须使用同一谓词，不能只过滤最终 top-k；否则其他项目结果会占满候选集并造成召回质量/侧信道问题；
- `HybridRetriever.search()`、`RagService.search()`、`LongTermMemoryManager.recall()` 签名都强制传 `ProjectScope`；
- 加 architecture test 或类型测试，禁止 Chat 调用无 scope recall。

### 8.2 Conversation 与 Redis

保留全局唯一 cid 后，`msgs:{cid}` 和 `summary:{cid}` 不会发生跨项目 key 碰撞。S1 的安全边界在访问 Redis 之前：

1. 先用 `project_id + cid` 验证 Conversation；
2. 验证成功才调用 ShortTermMemory；
3. 跨项目请求不得读取、清除或回填对应 Redis key。

不要把 Redis 当授权源。未来若取消 cid 全局唯一，再另行迁移 key；S1 不做双重作用域字段。

## 11. 可复制的双项目隔离演示

前置：

- 后端运行在 `http://localhost:8000`；
- PostgreSQL/Redis/Ollama 已启动并已拉取 `bge-m3`；
- 本脚本只用 Memory 保存/召回，不调用真实 Chat LLM。
- 完整脚本必须由 `codeaware-py/scripts/demo_s1_project_isolation.sh` 创建并在 `trap` 中销毁专用测试数据库/Redis namespace；因为 S1 没有 Project delete，禁止对共享开发库运行。

```bash
set -euo pipefail

: "${CODEAWARE_DEMO_ISOLATED:?must point to disposable demo environment}"

api_base="http://localhost:8000"
demo_suffix="$(
  python -c 'import uuid; print(uuid.uuid4().hex[:12])'
)"
cross_delete_body="$(mktemp -t codeaware-cross-project-delete.XXXXXX)"
trap 'rm -f "${cross_delete_body}"' EXIT

project_a_json="$(
  curl -sS -X POST \
    -H 'Content-Type: application/json' \
    -d "{\"slug\":\"isolation-a-${demo_suffix}\",\"name\":\"Isolation A ${demo_suffix}\"}" \
    "${api_base}/api/projects"
)"
project_b_json="$(
  curl -sS -X POST \
    -H 'Content-Type: application/json' \
    -d "{\"slug\":\"isolation-b-${demo_suffix}\",\"name\":\"Isolation B ${demo_suffix}\"}" \
    "${api_base}/api/projects"
)"

project_a="$(
  printf '%s' "${project_a_json}" |
    python -c 'import json,sys; print(json.load(sys.stdin)["data"]["id"])'
)"
project_b="$(
  printf '%s' "${project_b_json}" |
    python -c 'import json,sys; print(json.load(sys.stdin)["data"]["id"])'
)"

memory_a_json="$(
  curl -sS -X POST \
    -H 'Content-Type: application/json' \
    -H "X-Project-ID: ${project_a}" \
    -d '{"content":"shared-query marker belongs only to PROJECT_A","memory_type":"FACT"}' \
    "${api_base}/api/memory/long-term"
)"
memory_b_json="$(
  curl -sS -X POST \
    -H 'Content-Type: application/json' \
    -H "X-Project-ID: ${project_b}" \
    -d '{"content":"shared-query marker belongs only to PROJECT_B","memory_type":"FACT"}' \
    "${api_base}/api/memory/long-term"
)"

memory_a="$(
  printf '%s' "${memory_a_json}" |
    python -c 'import json,sys; print(json.load(sys.stdin)["data"]["id"])'
)"

result_a="$(
  curl -sS \
    -H "X-Project-ID: ${project_a}" \
    "${api_base}/api/memory/long-term/search?query=shared-query%20marker&threshold=0.0&top_k=10"
)"
result_b="$(
  curl -sS \
    -H "X-Project-ID: ${project_b}" \
    "${api_base}/api/memory/long-term/search?query=shared-query%20marker&threshold=0.0&top_k=10"
)"

python - "${result_a}" "${result_b}" <<'PY'
import json
import sys

a = json.loads(sys.argv[1])["data"]
b = json.loads(sys.argv[2])["data"]
assert a and b
assert all("PROJECT_B" not in row["content"] for row in a), a
assert all("PROJECT_A" not in row["content"] for row in b), b
assert any("PROJECT_A" in row["content"] for row in a), a
assert any("PROJECT_B" in row["content"] for row in b), b
print("two-project search isolation: PASS")
PY

status="$(
  curl -sS -o "${cross_delete_body}" -w '%{http_code}' \
    -X DELETE \
    -H "X-Project-ID: ${project_b}" \
    "${api_base}/api/memory/long-term/${memory_a}"
)"
test "${status}" = "404"

result_a_after="$(
  curl -sS \
    -H "X-Project-ID: ${project_a}" \
    "${api_base}/api/memory/long-term/search?query=PROJECT_A&threshold=0.0&top_k=10"
)"
python - "${result_a_after}" <<'PY'
import json
import sys
rows = json.loads(sys.argv[1])["data"]
assert any("PROJECT_A" in row["content"] for row in rows), rows
print("cross-project delete is a no-op: PASS")
PY
```

演示证据需要保留：

- 两个 Project UUID；
- A/B 搜索输出；
- 跨项目删除的 404 body；
- 删除后 A 数据仍存在的输出。

自动测试还必须覆盖 Conversation、Knowledge、CR/UT 和 AI ReadMe，不能用这一个 Memory 演示代替完整矩阵。
重复运行必须产生新的 `demo_suffix`，并由外围脚本删除整个 disposable 数据库/Redis namespace；“slug 不冲突但永久堆积测试行”不算可重复演示。
