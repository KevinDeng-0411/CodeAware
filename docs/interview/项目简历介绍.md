## 精简版（3-4 行,适合项目列表）

**CodeAware — AI 研发效能平台** | FastAPI + PostgreSQL/pgvector + DeepSeek + React

针对**软件工程实验室团队**开发痛点（代码评审周期长、新人上手慢、团队知识散落）从 Java 全量重构为 Python。核心是带**两级记忆（短期 Redis + 长期 pgvector）和混合检索（BM25 + 向量 RRF 粗排 + ONNX reranker 精排）的 Chat**——不是简单调 API,而是自设计 **8 事件 typed SSE 协议**管理流式、事务和故障语义,并用 LangGraph 做检索层智能路由+自我纠错。知识库支持**元素感知分块**（DOCX/HTML/PDF 按标题切,扫描版 PDF 显式拒绝）。后端 **350 测试**通过,60 条 golden 检索基线 fused MRR **0.941**（含 reranker）。Agent 模式带 **LLMOps 闭环**（run trace 回放 + 失败沉淀入 eval 回归集 + 请求边界 guardrail）。

## 标准版（6-8 行,适合项目经历栏）

**项目背景**：为**软件工程实验室团队**提供 AI 辅助的研发效能平台,解决三个具体痛点——① 代码评审依赖人工、反馈慢；② 新人上手需要反复查规范、问老成员,知识传递效率低；③ 团队文档散落在各处,没统一检索入口。从 Java（Spring Boot + LangChain4j）全量重构为 Python,提供 Chat、Code Review、Unit Test、AIReadMe、Knowledge、Memory、Prompt 七项能力。

**核心设计**：
- 以 **Chat 为核心域**,自设计 **10 事件 typed SSE 协议**（started/context.warning/context.references/reasoning.delta/token.delta/tool.call/tool.result/post_turn.warning/completed/failed）,严格 `PG commit → Redis refresh` 一致性模型,外部 LLM 等待期间不持有数据库事务
- **双模式（前端可切换 RAG/Agent）**：默认确定性 RAG 状态机（快省稳）+ 可选 ReAct Agent 工具循环（模型自主选工具、多步推理,thinking 模式 reasoning_content 逐轮回注,5 工具,前端模式按钮 + 工具轨迹可视化,ADR-0016）
- **LLMOps 闭环（ADR-0017）**：每轮 Agent run 落结构化 trace（思考/工具/观察/答案按序）+ 上下文快照（短时记忆摘要+窗口、长时记忆注入）→ 前端 Agent Runs 页回放（时间线 + 三层架构流程视图步进高亮 + doc/对话/记忆三处跳转）→ 失败 run 评审 accepted 自动沉淀进 eval 回归集 → 请求边界 guardrail fail-closed → memory 抽取/召回 Kafka 计数
- **两级记忆**：短期（PG 完整消息 + Redis 最近窗口 + 增量摘要,水位线条件更新） + 长期（LLM 抽取原子事实,内联 bge-m3 1024 维向量,pgvector cosine 跨会话召回）
- **混合检索**：BM25（ParadeDB pg_search）+ pgvector cosine → RRF 粗排 + ONNX cross-encoder 精排,60 golden **fused MRR 0.941**,稀有标识符 MRR 1.000;reranker 用 ONNX Runtime 落地（ADR-0009,MRR +0.058）
- **元素感知分块**：unstructured partition + 类型感知序列化（Title→`#`、ListItem→`-`）,PDF 用 pdfminer 字号标题检测,扫描版显式拒绝

**技术栈**：FastAPI + LangChain（ChatDeepSeek）+ SQLAlchemy 2 async + PostgreSQL 16/pgvector/pg_search + Redis 7 + Ollama bge-m3 + React/Vite | 350 后端测试 + 53 前端测试 | 10 表 37 API | 17 ADR | Celery + Kafka 异步 | C1-C6 阶段 evidence

## 深度版（面系统设计/架构岗）

### 项目概述

CodeAware 是为**软件工程实验室团队**设计的 AI 研发效能平台,从 Java（Spring Boot + LangChain4j 四模块）全量重构为 Python。针对实验室三个具体痛点：① 代码评审依赖人工、反馈慢；② 新人培训靠老成员口头传帮带,知识传递效率低；③ 团队文档（编码规范、架构设计、项目复盘）散落各处,没统一检索。提供 **Chat、Code Review、Unit Test、AIReadMe、Knowledge、Memory、Prompt** 七大功能,当前处于本地单用户阶段（团队化路线已规划：S1 项目隔离 → S2 分层重构 → S4 只读工具 Agent → S5 仓库感知）。以 **Chat 为核心域**,其余模块复用 Prompt 版本化 + 结构化输出 + 持久化基建。

### 架构决策与实现

**1. 自设计 typed SSE 协议（10 事件）**

裸 `data: token` + `[DONE]` 无法证明数据库提交成功,也区分不了"降级"和"失败"。设计 10 事件类型：`chat.started`（USER 已 commit,带真实 cid）→ `context.warning`（增强降级）→ `context.references`（检索来源,可溯源 RAG）→ `reasoning.delta`（模型思考过程流式）→ `token.delta`（生成内容）→ `tool.call` / `tool.result`（Agent 工具轨迹）→ `post_turn.warning`（后处理降级）→ `chat.completed`（ASSISTANT 已提交 + 全部收口）/ `chat.failed`。每个事件带 `protocol_version=1` + `sequence` 严格递增 + `turn_id`。同步接口 drain 同一事件流,状态机只有一份。

**2. PG-first 一致性模型**

`PG commit → Redis refresh`,而非常见的 Redis-first。USER/ASSISTANT 先写 PG 并 commit,再刷新 Redis 缓存（最近 20 条,TTL 7 天）。Redis miss → 回查 PG 并精确重建缓存,不盲目 append。增量摘要 `summary_message_count` 水位线 + PG 条件更新实现乐观并发控制,旧结果不覆盖新摘要。

**3. 短事务 + 外部调用分离**

LLM/embedding 等待期间不持有数据库事务：`短事务 PG 读写 → 关闭 session → 外部 LLM/embedding → 新短事务落结果 → commit`。RAG 查询先 `prepare_search`（查询改写 + embedding 预生成）再进入纯 SQL 的 `search_prepared`,一条 SQL 也不跨网络。

**4. 混合检索：BM25 + pgvector → RRF**

| 组件 | 实现 |
|---|---|
| 向量腿 | bge-m3 1024 维,HNSW cosine,`ORDER BY cosine_distance LIMIT top_k*3` |
| 词法腿 | ParadeDB pg_search 真 BM25（default tokenizer）,pg_trgm 为回退后端 |
| 融合 | RRF `1/(60+rank)`，结果标记 match_type（vector/keyword/both） |
| 多查询 | QueryRewriter 生成增强主查询 + 2-3 变体,去重后取 Top-K |

60 条 golden 基线（中文/英文/稀有标识符/语义改写/负例/跨文档）,RRF 融合 MRR **0.934**（C3 pg_trgm 仅 0.906,纯向量 0.920）,稀有标识符 MRR **1.000**;加 ONNX reranker 精排后 **MRR 0.941**（+0.058）。C4 BM25 升级后 fused 反超纯向量,实现 1+1>2。

**5. 元素感知文档分块 + PDF 字号标题检测**

解析器类型感知序列化（Title→`#`、ListItem→`-`）,分块器 `chunk_by_title` 一行没动,最小改动面让 DOCX/HTML/PDF 从定长滑窗恢复为按标题切。PDF 走 pdfminer 直接布局分析（字号众数=正文,>正文+0.5pt 且 ≤12 词=标题）,不走 `unstructured.partition.pdf`（避 torch/opencv/onnxruntime 视觉模型栈）。扫描版 PDF 通过 pypdf 文本层探针显式拒绝（`KNOWLEDGE_PDF_NO_TEXT_LAYER`）。

**6. Chat 引用与思考过程（C6）**

`context.references` 下发实际注入 prompt 的知识 chunk + 记忆,前端可折叠来源卡片（带 match_type 徽标）;`reasoning.delta` 流式展示模型原生思考,前端可折叠窗 + 答案开始后自动收起。关键坑：`ChatOpenAI` 不提取 `reasoning_content`（langchain 官方明示 third-party 字段丢弃）,切 `ChatDeepSeek` 后 spike 验证通过。

**7. 工程化与安全测试**

- 后端 350 tests，前端 53 tests，37 API，10 数据表，Alembic head 0012
- `run_tests_safe.py`：每次创建随机 disposable PG/Redis，拒绝 `ai_center`/`ai_center_py`/Redis DB 0,无论成功失败中断都精确清理
- 17 篇 ADR（0001-0017）记录所有架构决策
- Celery 异步任务（文档解析、记忆抽取）+ Kafka 事件流（audit/metrics）
- C1-C6 阶段 evidence manifest 可机器验证

**8. LLMOps 闭环（ADR-0017）——把 Agent 从"黑盒"变成"可观测、可评测、可改进"**

围绕三个痛点落地：**Agent 黑盒、失败不沉淀、无 guardrail**。

- **run trace 持久化 + 回放**：`agent_runs` 表（turn_id 全局唯一），`react_loop` 累积 trace（thought/tool_call/tool_result/answer 按序 + 工具 doc_ids）+ `context_snapshot`（本轮注入的短时记忆摘要+窗口边界、长时记忆 memory_refs）。turn_coordinator 成功/异常/取消三终端点 best-effort 落库（写失败不 fail turn）。回放端点归属 JOIN 校验。**trace 默认只存元数据**（思考全文靠 `AGENT_TRACE_INCLUDE_REASONING=true` 打开，避免 JSONB 膨胀与隐私）。
- **失败沉淀 → eval 回归集**：`needs_review` 分层（error/empty/工具真实异常），前端 Agent Runs 页评审 accepted（填 expected_tools + category）→ `sync_regression_cases.py` 自动追加进 eval 的 `REGRESSION_CASES`——线上失败 run 变成门禁样本，"可持续改进"不靠人肉。
- **请求边界 guardrail（fail-closed）**：注入检测放在 `ChatRequest` validator（422 拒绝），刻意不在工具结果层做（知识库是策展内容，结果层模式匹配会误报且伤模型理解）。
- **前端 Agent Runs 页**：列表/统计/详情回放；**流程视图 = 三层架构**（静态 SVG + 事件流 + STAGE 映射表 + CSS class 切换点亮），事件源无关（回放喂 trace，未来实时喂 SSE）；doc 节点跳知识库、查看对话跳完整上下文、记忆区跳 Memory 页。
- **Memory-Ops 两 counter**：recall（RAG/Agent 双路径）+ extraction（含 count=0）→ `metrics.memory` Kafka 事件。

### 已知边界（面试时主动说明）

- 当前为**本地单用户/单进程**,per-conversation guard 非跨进程 lease
- Agent 模式是**检索层决策形态**（只读 5 工具），不执行外部动作：sandbox/patch/shell/审批/Git 写入/MCP/多 Agent 仍锁（S1-lite→S5-lite 逐阶段授权）
- RRF 粗排 + ONNX cross-encoder 精排（bge-reranker-v2-m3,MRR 0.941）
- 引用是"参考来源"（检索结果透明化）,不依赖 LLM 显式 cite
- 思考过程默认不持久化（`agent_runs.trace` 只存元数据；`AGENT_TRACE_INCLUDE_REASONING=true` 才存全文）
- Chat 页实时高亮（P2）未做——FlowTrace 三层架构事件源无关已预留，未来换 SSE 数据源即可
- 扫描版 PDF 不支持 OCR
- PDF 表格压平为纯文本流（pdfplumber extract_tables 已评估、无表格文档暂缓）
